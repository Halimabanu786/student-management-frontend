Student Management System — Frontend Architecture

Complete File & Folder Explanations, React 18 Hooks, Axios Integration, and Interview Q&A

1. High-Level Frontend Architecture

The frontend is a Single Page Application (SPA) built with React 18 and bundled using Vite. Unlike multi-page applications, the browser never reloads the whole page. React dynamically manipulates the DOM in memory via the Virtual DOM based on reactive state changes.

[👤 User Action] (Clicks Add, Edit, Delete, or Types in Search)
↓
[⚛️ React Component] (App.jsx captures event)
↓
[🔄 State Management] (useState updates formData / students list)
↓
[📡 Service Layer] (studentService.js encapsulates Axios calls)
↓
[🚀 Express Backend] (REST API at http://localhost:5000/api/students)
↓
[🍃 MongoDB Atlas] (Performs live CRUD operation and returns JSON)
↓
[⚡ Re-render] (Virtual DOM diffs changes and updates the browser instantly)

2. Directory & File-by-File Breakdown

📄 index.html (Single HTML Root Page)

Purpose: The sole HTML file for the entire application. When a user navigates to the app, the web server delivers this file.

<div id="root"></div>
<script type="module" src="/src/main.jsx"></script>
💡 Interview Question & Ideal Answer: "Why is index.html mostly empty in a React project?"
"Because React is an SPA framework. Rather than serving multiple static HTML pages, React mounts our entire JavaScript component tree into the single <div id='root'> container and manages view changes dynamically without full browser reloads."

📄 package.json (Dependencies & Build Scripts)

Purpose: Lists the project's metadata, executable scripts, and external library dependencies.

  • react & react-dom: The core React UI library and DOM reconciliation engine.
  • axios: Promise-based HTTP client used to interact with our Node.js/Express backend.
  • vite: The next-generation build tool and local development server.
💡 Interview Question & Ideal Answer: "What is the difference between dependencies and devDependencies?"
"dependencies (like React and Axios) are bundled into the final production code because the application needs them at runtime in the user's browser. devDependencies (like Vite) are developer tooling used solely on your local machine to build, compile, and bundle the app."

📄 vite.config.js (Vite Tooling & API Proxy)

Purpose: Configures Vite plugins, local development port (5173), and the optional API reverse proxy.

import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  server: {
    port: 5173,
    proxy: { '/api': 'http://localhost:5000' }
  }
});
💡 Interview Question & Ideal Answer: "Why choose Vite over Create React App (Webpack)?"
"Vite leverages native browser ES Modules (ESM) and the ultra-fast Esbuild bundler. It starts development servers instantly and provides near-instantaneous Hot Module Replacement (HMR) without having to re-bundle the whole project on every file save."

📄 src/main.jsx (JavaScript Application Entry)

Purpose: The JavaScript entry point that mounts the root React component tree into the DOM.

import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App.jsx';
import './index.css';

ReactDOM.createRoot(document.getElementById('root')).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);
💡 Interview Question & Ideal Answer: "What is the purpose of <React.StrictMode>?"
"StrictMode is a developer tool that activates extra checks and warnings. In development mode, it intentionally mounts, unmounts, and re-mounts components to catch memory leaks, verify that useEffect cleanup functions work, and detect deprecated APIs."

📄 src/services/studentService.js (API Service Layer)

Purpose: Isolates all HTTP requests into a modular service layer using Axios, separating UI logic from network endpoints.

import axios from 'axios';

const API_URL = 'http://localhost:5000/api/students';

export const getStudents = (search = '') => 
  axios.get(search ? `${API_URL}?search=${search}` : API_URL);

export const addStudent = (studentData) => 
  axios.post(API_URL, studentData);

export const updateStudent = (id, studentData) => 
  axios.put(`${API_URL}/${id}`, studentData);

export const deleteStudent = (id) => 
  axios.delete(`${API_URL}/${id}`);
💡 Interview Question & Ideal Answer: "Why create a separate service layer instead of calling Axios directly inside App.jsx?"
"It adheres to the Single Responsibility Principle. Components should only manage UI rendering and user interactions. Encapsulating network requests in a service layer makes code cleaner, prevents URL duplication, and allows changes to backend endpoints to happen in a single place without touching UI components."

📄 src/App.jsx (Main Component & State Orchestrator)

Purpose: The core component managing data flow, modals, user alerts, and CRUD operations.

  • useState for Data: students (list from MongoDB), search (search query), loading (spinner flag).
  • useState for Modals: showModal (true/false), editId (null for Add, MongoDB _id for Edit), formData (form fields).
  • useEffect for Data Lifecycle: Calls fetchStudents(search) on initial page load and whenever search changes.
// Dual-Purpose Submit Handler (Add vs Edit)
const handleSubmit = async (e) => {
  e.preventDefault(); // Prevents full browser reload
  try {
    if (editId) {
      await updateStudent(editId, formData); // HTTP PUT
      notify('Student updated successfully!');
    } else {
      await addStudent(formData);            // HTTP POST
      notify('Student added successfully!');
    }
    setShowModal(false);
    fetchStudents(search); // Refresh list from MongoDB Atlas
  } catch (err) {
    notify('Operation failed', 'error');
  }
};

3. Core React Concepts Deep-Dive (Interview Essentials)

Concept How It Is Implemented in Code Why We Do It / Interview Answer
Controlled Components <input name="fullName" value={formData.fullName} onChange={handleChange} /> React state is the "single source of truth". The input value is driven by state, preventing out-of-sync DOM bugs.
Computed Property Names setFormData({ ...formData, [e.target.name]: e.target.value }) Allows a single change handler function to handle all 7 form inputs dynamically based on the input's name attribute.
Dependency Array in useEffect useEffect(() => { fetchStudents(search); }, [search]); Controls when the side-effect executes. Passing [search] triggers data fetching on mount AND whenever the user types in the search bar.
List Keys students.map(s => <tr key={s._id}>...</tr>) Gives each DOM node a stable identity. The Virtual DOM uses keys to reorder or update items without re-rendering the whole table.
Conditional Rendering loading ? <Spinner /> : students.length === 0 ? <Empty /> : <Table /> Renders distinct UI states (loading, empty, populated) based on boolean flags and array lengths in state.

4. Top 10 Technical Interview Questions & Answers

Q1: What happens under the hood when a user clicks "Add Student" and clicks Save? "1. Each keystroke updates formData via handleChange.
2. Clicking Save fires handleSubmit. e.preventDefault() stops the default browser form submission.
3. The component calls addStudent(formData) from our service layer, which issues an HTTP POST request to Express.
4. Express validates the schema and inserts the document into MongoDB Atlas.
5. On response, React closes the modal, triggers a green notification toast, and invokes fetchStudents() to synchronize the table with the database."
Q2: Why did you use Axios over the native browser fetch() API? "Axios has 3 major advantages:
1. Automatic JSON transformation: Parses JSON automatically without needing res.json().
2. Direct Error Rejection: Automatically throws on 4xx/5xx status codes, simplifying try...catch error handling.
3. Built-in Interceptors & Timeouts: Provides easier configuration for request headers and request cancellations."
Q3: How does the search bar work in real-time? "The search input is two-way bound to the search state. Whenever the user types, the state updates. Because search is in the dependency array of useEffect, the effect calls fetchStudents(search), sending /api/students?search=... to Express. The backend runs a case-insensitive MongoDB regex query on both full name and student ID."
Q4: How does the Edit operation load existing data into the form? "When the user clicks 'Edit', openEditModal(student) is called. It sets editId to that student's MongoDB _id and pre-populates formData with their existing properties. When the form is submitted, handleSubmit detects that editId exists and issues an HTTP PUT instead of a POST."
Q5: How do you prevent accidental deletions? "We wrap the delete call in window.confirm('Are you sure you want to delete...'). Only if the user confirms does React execute deleteStudent(id) to send the HTTP DELETE request to Express."

When the interviewer says: "Walk me through your frontend codebase:"

I structured the project using the Service Layer pattern. In src/services/studentService.js, I centralized all Axios HTTP calls for our 4 CRUD operations. This separates network concerns from user interface logic.

In src/App.jsx, I used core React hooks: useState manages reactive state for the student roster, controlled form inputs, and modals; useEffect coordinates initial data loading and synchronizes with real-time search queries.
